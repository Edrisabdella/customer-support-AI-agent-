# Project Reflection

A key design decision was to keep customer-support orchestration inside one Strands agent while exposing backend actions through the AgentCore Gateway. This keeps the agent responsible for deciding which capability is appropriate while MCP provides a consistent interface to the order-tracking API and refund Lambda. I also kept the Knowledge Base, Memory, Code Interpreter, and Browser as explicit tools so the system prompt can make the routing policy clear and auditable.

One concrete challenge was maintaining compatibility between the project starter material and the current MCP transport naming. The starter document references `streamable_http_client`, while current AWS examples use `streamablehttp_client`. The implementation uses a compatibility import so the project remains aligned with the course starter while supporting the current SDK naming. The same configuration approach is used for the model ID, because the uploaded project document mentions Nova Lite in the environment setup while the starter `main.py` explicitly specifies `global.amazon.nova-2-lite-v1:0`.

For production, the next priority would be security and durable backend state. The demonstration Lambda functions intentionally use mock data; a production order/refund service should use authenticated APIs and a durable database with idempotency and authorization checks. Secrets should never be stored in source code. Operationally, CloudWatch error alarms, structured logs, latency/error metrics, and distributed tracing should be used to detect failures early. The AgentCore Gateway should expose only the minimum tools required by the agent, with least-privilege IAM and controlled network access. These changes preserve the project architecture while making it safer and more scalable for real customer traffic.
